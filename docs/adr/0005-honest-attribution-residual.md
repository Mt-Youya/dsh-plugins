# 归因缺口必须显式暴露，禁止无限等比摊平

字符估计与精确 usage 总量之间总有差额。最省事的做法是等比缩放把所有分桶摊到总量上——面板立刻「合得上」，但代价是撒谎：全库 121 个 Claude 会话文件里有 56 个没有 `prompt_snapshot`，工具 schema（在一个 430K 窗口里占 95%+ 的前缀）完全不可见；等比放大这些轮次时实测最坏系数达 17.7×，面板会把「历史」画成占 94% 的窗口，而真相是那一块根本看不见。

**决策**：只有当差额可归因于测量误差（`|factor−1| ≤ 0.25`）且没有整类缺失时才等比缩放；否则保持原始估计，把缺口写进 `Attribution.residual`，视图画成「未知」切片。缩放过的轮次记 `reconciled.factor`，让读者能判断图里有多少是测量、多少是摊派。

**Consequences**：部分会话的面板会有一块明显的「未知」，看起来不如闭合的分区漂亮——这是有意的。`docs/IR.md` 与 PLAN 的精度决策都以本条为准。
