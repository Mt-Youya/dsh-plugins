# 归因按分块投影，不做逐请求增量差分

有一种更"准"的做法：用相邻请求 `input_tokens` 的差值，把两次请求之间新增的内容按大小摊到各来源上。它能消掉大部分 `residual`，但它归因的是**增量**而不是**构成**——压缩会把窗口整体替换，缓存命中与否不影响 prompt 大小，这两件事都会让差值失去意义；而且一旦把区间内容摊到各来源，就等于用另一套假设替换了 `residual`，ADR 0005 的诚实边界随之失效。

**决策**：v1 归因一律按"该轮峰值请求的分块投影 + 无法归因的显式 residual"。逐请求差分留作 v1.1 候选，前置条件是先有一份对本语料实测校准过的分词器（当前 2.6 chars/token 的折算对指令体偏高约 23%，见 Codex adapter 的 `reconciled.factor` p50 = 0.769）。

**Considered Options**：投影 + residual（当前）；逐请求差分摊派（更贴合"新增了什么"，但把测量误差换成了假设）。
