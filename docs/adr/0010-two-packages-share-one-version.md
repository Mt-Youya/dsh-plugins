# 0010 · 成员包与集合包共用同一个发布版本号

- 状态：已接受
- 日期：2026-11-04

## 背景

集合包自包含后（ADR 0009），两个包承载的是同一份插件代码。历史做法是各自独立 bump（成员 0.0.6、集合 0.0.5），结果出现：registry 上 0.0.6 与仓库 0.0.6 内容不同；`/health` 报的是生效包版本，永远和另一个包对不上；用户无法用版本号判断“新功能是否已交付”。

## 决定

1. 每次发布把成员包与集合包 bump 到**同一个版本号**，先发成员包、再发集合包。
2. `/health` 与版本检查展示的是“生效包”的版本；统一版本后两种安装渠道的数字一致。
3. 版本检查比较的是生效包在 registry 上的同包最新版本。

## 后果

- 不能只给集合包发“纯打包修复”；任何发布都是成对的。
- 版本号成为判断交付内容的唯一依据，RELEASE.md 的发布步骤需随之更新。
